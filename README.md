# IWASON SPIRE — じっと教の塔

ブラウザで遊べる、ターン制デッキ構築ローグライクです。**5職業から選び、各12フロア・全3Actの塔を攻略します。Actが変わるたびに特別な祝福を受け取れます。** 既存の単体戦闘も練習モードとして残しています。

## ブラウザでテストプレイする

**[ブラウザで遊ぶ](https://sunnytruck.github.io/spyier/)** を開き、「第1階層へ進む」→職業を選択→「この職業で探索を始める」→じっと神の祝福を選択して開始します。プレイヤー側にNode.jsやコマンド入力は不要です。

PublicリポジトリのPages有効化と、[既存版のデプロイ成功](https://github.com/sunnytruck/spyier/actions/runs/39535060575)を確認済みです。以後は `main` へのpushで、テスト・ビルド成功後に公開版も自動更新します。設定をやり直す場合の手順や、セーブへの影響は [公開手順](docs/github-pages.md) を参照してください。

## 開発者向けの起動

Node.js 22.12 以降と npm が必要です。この環境では Node.js 24 を使っています。APIキー、画像のダウンロード、データベースは不要です。

```bash
cd /workspace/spyier
npm ci
npm run dev
```

上記は**コードを編集する開発環境のターミナル**へ入力するコマンドです。`/workspace/spyier` はCodexクラウド側の作業場所で、WindowsのPCにそのまま存在するフォルダではありません。自分のPCで開発する場合は、Node.jsをインストールし、このリポジトリをダウンロードしたフォルダをVS Codeで開き、「ターミナル → 新しいターミナル」で `npm ci` と `npm run dev` を順に実行します。

サーバーが起動したPCのブラウザで `http://localhost:5173/spyier/` を開きます。クラウド環境のサーバーへ自分のPCから接続する場合は、環境のポート転送機能が必要です。遊ぶだけなら上の公開URLを使ってください。

```bash
npm test          # Vitest: 戦闘・探索・マップ・保存の回帰テスト
npm run build    # TypeScript型チェックと本番ビルド
npm run preview  # dist/をポート4173で起動
```

本番ビルドのローカル確認URLは `http://localhost:4173/spyier/` です。Viteの `base` は `/spyier/` に固定しています。

## 現在遊べる内容

- 接続と部屋配置が毎回変わるシード付き12フロアの分岐マップ。安全な経路とエリートに2回挑める経路、全ノードからボスへの到達を保証。全体のスクロール・拡大・現在地への移動にも対応。
- 新規探索は全3Act。各Actのボス報酬を受け取ってから次のActへ進みます。登場人物6人・祝福19パターンから、シードで固定した4択を提示。カード削除・強化・変化、HP・ゴールド・レリック、職業札・限定札と代償を確認して受け取ります。
- 1〜3体の敵と、それぞれの行動予告・対象選択・状態異常。
- 5職業の選択と、職業別のHP・初期デッキ・初期レリック・カードプール。
- 添付TXT574件の参照カタログ。参照付き240種類の通常・強化効果を実装（基本札・生成専用3種類・祝福限定8種類を含む）。今回42種類を追加（拳僧6・影師8・法王6・霊僧6・機巧師6・無色10）。独自30種類・既存の呪い1種類を合わせ、実装定義は271種類。
- 星・鍛造・召喚・破滅・魂札・雷/霜オーブ・集中力、選択式の捨て札/廃棄/回収/山札戻し、保留・エセリアル・天賦・Xコスト。条件付き効果、手札全交換、一時強化、次ターン予約、エナジー・ブロック倍化にも対応。
- 敵21種類（通常13・エリート5・ボス3）と、Act 2・3向けの42派生定義。派生は同じ戦術の段階的な強化です。通常敵には練習用の番人を含みます。階数別編成、仲間支援、カードへの反応、型の変化、岩霊にも届く全体攻撃があります。
- レリック198定義。添付資料294件のうち173件を実装し、旧独自25件も維持。5職業のスターター通常版・強化版、戦闘フック、取得時の選択と交換、経済・施設の効果に対応。通常・ショップ・イベント・エンシェントを別プールにし、職業制限も適用します。ポーション5種類、初期所持枠3つ（レリックで拡張可能）。
- 戦闘後の自職業3択カード報酬とスキップ、レリック報酬、ゴールド、ポーション獲得。ボスは自職業のレアカードだけを3枠提示し、候補が3種類以上あれば重複しません。影師にもレア候補を追加し、全5職業で異なるレア3種類を提示可能です。通常・エリートはレアリティ抽選を使用。ショップは自職業2枚と無色1枚で価格もレアリティ別。祝福限定・生成専用は通常取得に混ぜません。
- 商人でのカード・レリック・ポーション購入と、一度限りのカード除去。
- 休憩所での回復または強化、25種類のランダムイベント。直近3種類を避けて抽選し、職業専用イベントは該当職業だけに出現します。
- 勝利・敗北・再挑戦、途中セーブと正確な再開、日本語UI、戦闘速度・演出設定。

## 遊び方と戦略

初期HPは職業ごとに72〜80、エナジー3、毎ターン5枚ドロー、初期デッキ10枚です。山札が尽きると捨て札をシャッフルします。手札はPCではクリック、または `1`〜`5` キーで使用できます。スマートフォンではタップで詳細を確認してから使用します。手札は画面下部に残り、多い場合は手札領域だけを横にスクロールできます。ホバー・詳細ボタンで、長い効果説明も画面内に拡大表示します。敵をクリックして対象を選び、「ターン終了」または `E` で敵の行動へ進みます。捨て札・廃棄を要求された場合は、指定枚数を選び「選択を確定して続ける」を押します。全員を倒すと勝利、HPが0になると敗北です。

カードを対象へドラッグして使う操作にも対応しています。無効な場所へ放すと、消費せず手札へ戻ります。攻撃・被弾・盾・状態異常・職業固有効果、ドローや捨て札を2D演出で表示します。演出中の「演出をスキップ」と、設定の速度・軽量化・動きの短縮を利用できます。[演出と拡張方法](docs/battle-presentation.md)も参照してください。

職業を選ぶと岩尊けいとの姿・装備・専用HUDが変わります。機巧師のオーブは空き枠と右端の解放予告、霊僧の岩霊は独立したHP・護衛・攻撃、法王の星はエナジーの隣で総数と当ターンの獲得数を表示します。拳僧の筋力・HP消費、影師の石刃強化・毒予測も常時確認できます。各表示をクリック／タップすると詳しい説明を開き、手札や戦闘中のカード一覧では「現在の効果」を確認できます。星を消費する別コストは追加していません。

詳しくは [職業別HUD](docs/class-combat-ui.md)、[キャラクター素材](docs/class-character-art.md)、[計算と表示の契約](docs/class-resource-rules.md)、[互換性・検証](docs/class-ui-validation.md) を参照してください。

今回の追加内容は [マップの生成ルール](docs/random-map.md)、[マップの操作](docs/random-map-ui.md)、[追加カードと現在の未実装334種類の一覧](docs/card-expansion-audit.md)、[共通効果](docs/card-effect-expansion.md)、[現在値の表示](docs/card-runtime-values.md)、[報酬と経済](docs/reward-balance.md) に記録しています。[今回の進捗](docs/roguelike-expansion-progress.md)から再開できます。

追加42枚・レリック16個の詳細と検証は [今回の進捗](docs/content-continuation-progress.md)、[拳僧・影師](docs/card-continuation-martial.md)、[法王・霊僧](docs/card-continuation-mystic.md)、[機巧師・無色](docs/card-continuation-arcane.md)、[レリック](docs/relic-continuation.md) に記録しています。敏捷・プレート・活力、山札からの選択廃棄、ランダム無色生成、対象指定の雷オーブ発動を共通処理で解決し、X効果補正と継続攻撃カウンターも表示・保存へ反映します。

続く祝福アップデートは [登場人物・抽選・代償](docs/blessings-rules.md)、[専用画面と演出](docs/blessings-ui.md)、[人物素材](docs/blessing-art.md)、[限定8枚の原文照合とルール](docs/blessing-card-audit.md)、[3Actの敵補正](docs/acts.md)、[検証結果](docs/blessing-validation.md)、[継続用の進捗](docs/blessing-progress.md) に記録しています。霊体は敵の攻撃だけを1ヒット最大1にし、毒・HP消費・最大HP消費は軽減しません。全札強化は戦闘中のみで、極光の炎に対応するカードの最大HP消費は探索中も持続します。

本文・カード効果・操作ボタン・敵の予告は日本語ゴシック体を基本にし、長い文章も折り返して表示します。タイトルなどの大きな見出しには従来の装飾書体を残しています。

休憩所では「教えを磨く」の一覧にある「強化後を表示」チェックボックスで、選択前から全候補を比較できます。個別の確認画面で「強化を確定する」まではカードを変更しません。ランダム強化イベントは選択肢を押すと一度だけ確定し、対象と実際の費用を保存される結果画面で確認します。デッキ・報酬・ショップの個別プレビューも引き続き利用できます。詳しくは [強化と結果表示の仕様](docs/card-upgrade-preview.md)を参照してください。

追加した内容の一覧は [敵12種](docs/enemy-expansion.md)、[レリック20種](docs/relic-expansion.md)、[イベント13種](docs/event-expansion.md) に記載しています。[大型アップデートの進捗](docs/large-update-progress.md)と[検証・バランスの記録](docs/expansion-validation.md)も参照できます。

- 敵は各自の予告どおりに行動します。複数敵の攻撃には同じブロックを順番に使います。倒した敵は行動しません。
- 筋力は攻撃の**各ヒット**へ加算されます。弱体は与ダメージ×0.75、脆弱は被ダメージ×1.5。最後に小数点以下を切り捨て、ブロックから先に引きます。
- 毒は対象のターン開始時にブロックを無視してダメージを与え、その後1減少します。弱体と脆弱は対象のターン終了時に1減少し、ブロックは次の自分のターン開始時に消えます。
- 筋力を得てから多段攻撃、防御を得てからブロック参照攻撃、毒を積んでから毒の倍化を使うなど、使用順で結果が変わります。
- パワーは戦闘中持続します。廃棄カードは同じ戦闘では山札に戻りません。報酬を見送ってデッキを小さく保つこともできます。
- HPと所持品は探索中に持ち越します。回復か強化か、危険なエリートに挑むか、ゴールドを何に使うかを判断してください。
- じっとゲージは維持しています。50以上で防御カードのブロック+2、100で神格化。「岩尊神拳」は神格化中に追加ダメージを与え、ゲージ消費後は神格化が解除されます。通常のターン経過では増えませんが、明記されたレリック効果では増えます。

上部のポーションは戦闘中にクリックして使います。敵対象のものは選択中の敵に作用します。カードや敵の状態、レリックの効果、山札・捨て札・廃棄札・発動済みパワーは画面から確認できます。

## 保存

探索はlocalStorageの `iwason-spire:run:v2`、練習は従来の `iwason-spire:save:v1`、設定は `iwason-spire:settings:v1` へ分けて保存します。探索画面、現在位置、手札、山札、捨て札、敵と予告、状態異常、RNG状態、報酬候補、商人の購入済み商品まで復元します。再読み込みで候補を再抽選しません。

破損や不正な状態は読み込まず、新規開始できます。保存が拒否されたブラウザでも現在のタブでは遊べます。別端末・別ブラウザ・別オリジンにはセーブを共有しません。

保存キーとバージョンは維持しています。職業IDがない旧探索は従来の30枚プールで再開し、新規探索のみ職業を選択します。新規探索では職業リソース、生成カード、手札選択待ちの処理も保存します。

保存済みマップと報酬は再抽選しません。新規探索のみ新しいレアリティ抽選を使い、旧ショップの価格は55ゴールドのままです。新ショップの価格、次ターンの予約効果、一時効果、回収・山札戻しの選択待ちも保存・復元します。

祝福の登場人物・台詞・4候補・カード選択の途中状態・受領明細と、各Actの完了履歴も保存します。読み込みで人物や候補を抽選し直さず、受領済みの報酬・代償を重ねて適用しません。Act項目のない旧セーブは従来の1Actを最後まで遊べます。途中の旧ランへ新しい祝福を挿入しません。

## 構成と拡張

```text
src/
  types/game.ts          戦闘の型
  types/run.ts           探索・画面・アクションの型
  data/                  独自カード・敵・レリック・ポーション・イベント
  engine/index.ts        createCombat / reduceCombat
  engine/combat/         ダメージ・複数敵・ターン・レリック
  engine/effects/        タグ付きの再利用可能なカード効果
  engine/run.ts          createBlessedRun / reduceRun / Act移行（createRunは旧互換）
  engine/blessings.ts    祝福の専用乱数・選択・確定・保存整合性
  engine/map/            シード付きマップ生成と接続検証
  engine/random.ts       保存可能な乱数とシャッフル
  engine/persistence.ts  練習のv1保存互換
  engine/runPersistence.ts 探索のv2保存と整合性検証
  components/            カード・オリジナルSVG・HUD・ダイアログ
  screens/               戦闘と探索の各画面
  tests/                 単体・統合・通しプレイのテスト
```

UIはreducerの返す状態を表示し、直接ゲーム状態を書き換えません。職業は `data/classes.ts`、実行可能カードは `data/classCards.ts`、取得プールは `engine/cardPools.ts`、固有リソースの共通処理は `engine/combat/resources.ts` にあります。表示名とは別のカードID・敵IDを変更・再利用しないでください。新規の3Act探索は `createBlessedRun(seed, classId)` を使います。既存の `createRun(seed, classId)` と引数省略の呼び出しは旧1Act方式を維持します。

参照カタログは `scripts/import-card-catalog.mjs --source-dir /path/to/attachments` をNode.jsで実行して再生成できます。原資料の不足・表記揺れは [解析記録](docs/card-catalog-audit.md)、初期86件は [職業・カード実装一覧](docs/class-system.md)、現在の全実装数と残件は [追加・未実装の監査](docs/card-expansion-audit.md) に記録しています。ゲーム内のカード図鑑でも、使用可能・生成専用・未実装・仕様確認待ちを確認できます。

## 開発方針と残課題

[更新した開発計画](DEVELOPMENT_PLAN.md) と [カード設計・参照資料の扱い](docs/card-design-reference.md) を参照してください。ユーザー添付のカード一覧から汎用的な効果構造を参考にし、画像・名称・説明文・キャラクターは独自のものを使っています。

残り334件の参照カードと、資料レリック121件は未実装・保留です。レリックの全件照合と個別理由は [レリック監査](docs/relic-implementation-audit.md)、今回の再開地点は [進捗メモ](docs/content-continuation-progress.md) に記録しています。各Act固有の追加敵戦術、音声、個別カードイラストも今後の課題です。未実装カードごとの理由を [監査一覧](docs/card-expansion-audit.md) に記録し、取得対象から除外しています。カード種別・レアリティと、資料にないキーワードの基本ルールは仮設定です。星消費量は推定して追加していません。

全3Actの職業間・ボス戦の難度は暫定です。通しプレイと実プレイヤーのフィードバックで調整します。自動操作の勝率は人間の勝率を表すものではありません。
