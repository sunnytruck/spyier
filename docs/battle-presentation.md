# 戦闘操作と2D演出

## 操作

- 手札をクリック、または対象へドラッグして使用する。攻撃・毒などの単体対象カードは生存中の敵へ、防御などはフィールドへ放す。全体対象はフィールドでも使用できる。
- 対象が有効ならガイドと対象枠が光る。無効な場所、画面外、Escape、ポインター取消では消費せず手札へ戻る。
- マウスとタッチに対応。狭い画面では手札の横スワイプを維持し、ドラッグ中は画面端でスクロールする。クリックと1〜5キー、Eでのターン終了も維持している。
- 演出中はカード・ターン終了・ポーションを同じ入力ロックで保護する。「演出をスキップ」は確定済みの結果へ進み、戦闘処理を再実行しない。
- 設定で通常・高速・即時、演出品質の自動・標準・軽量を切り替える。動きを抑える設定とOSの「視差効果を減らす」設定は、命令型のアニメーションにも適用する。

## 実装方式

現在のReact、Vite、TypeScriptとオリジナルSVGを維持し、Web Animations APIでキャラクターとカードを動かし、Canvas 2Dで斬撃・光・粒子を描く。新しい描画ライブラリや外部素材への依存は追加していない。

1. `captureCombatTransition` が公開reducerを一度だけ実行する。
2. 戦闘処理の境界で、一時的な意味イベントと表示用スナップショットを収集する。攻撃主体、対象、各ヒット、完全ブロック、死亡、札の移動、状態・職業リソースを記録する。
3. 計算後の本当の状態を直ちに保存する。
4. 独立したタイムラインが、カード使用→踏み込み→命中→被弾・数字→札の移動を順番に表示する。撃破演出が終わってから報酬・敗北画面を表示する。

観測にはオブジェクトをキーにしたWeakMapを使う。演出キュー、途中の表示スナップショット、タイマー、粒子を`CombatState`やlocalStorageへ追加しない。戦闘計算・乱数・カードのコスト・既存の保存キー/バージョンは変わらない。演出中に再読み込みした場合は、保存済みの計算結果から再開し、処理や報酬を二重に与えない。

## 効果の違い

攻撃は予備動作・踏み込み・斬撃/打撃・被弾、完全防御は盾とBLOCK表示、防御は盾の紋章、毒は緑の霧、筋力は上昇する岩片/矢印、パワーは金の魔法陣、回復は緑の光で表す。敵は行動中の1体だけが踏み込み、ダメージ数字はヒットごとに出す。

星は星粒、聖剣と鍛造は紫の剣光、石刃は細い投射、岩霊・魂・破滅は霊の軌跡、オーブは雷と霜の異なる描画を使う。オーブ・毒・反撃・自傷などで、攻撃していないキャラクターを踏み込ませない。

ドローは裏面から表面を見せながら手札へ移動し、廃棄は焼失する。生成カードは実際の生成先へ移動する。描画用に一時的に隠した手札は、完了・スキップ・取消・アンマウント時に復元する。

## 効果音の追加

ブラウザの`iwason:presentation`イベントを購読できる。`detail`は`{ kind, cue, phase: 'start' | 'end', sequence }`で、`cue`に`effect`、`sourceId`、`targetId`、`resource`、`card`などがある。音のアダプターで「attack開始」「impact開始」「resource: lightning」などを対応させる。エンジンやカード定義に音声再生処理を入れない。

`iwason:presentation-reset`はスキップ/取消通知で、残っている音やエフェクトの停止に使える。音声素材の再生は今回未追加で、ユーザー操作後のAudioContext初期化や音量設定は音声導入時に行う。

## 負荷と検証

60fpsを目標に、キャラクターと札は主にtransform/opacityで動かす。Canvasだけが必要な間requestAnimationFrameを回し、React更新は意味イベントの境界に限定する。描画中のCanvasは毎フレームDOMの座標を測り直さない。粒子・数字・カード面キャッシュを制限し、軽量では粒子数、同時に見せる札、Canvasの解像度を減らす。長い行動は通常4秒・高速1.8秒以内を基準に演出時間を調整する。

端末ごとの60fpsを保証するものではない。実機で重い場合は軽量・高速・短縮を選択できる。機能の正しさは、全116カードの通常/強化に対する演出有無での状態・乱数・セーブ完全一致、ヒット順・死亡・選択待ち、対象判定、タイムラインの手動クロック、ブラウザでの連打/ドラッグ/スキップ/再読み込みで検証する。
