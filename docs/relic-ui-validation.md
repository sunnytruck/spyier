# レリック更新の画面検証

今回の検証はローカルの Vite サーバーを Chromium で開き、Playwright で実際のクリック・タップと再読み込みを実行したものです。戦闘画面のコンパクト化は別途 `docs/combat-compact-validation.md` に記録します。

## 検証方法

- PC 相当は 1366×768、スマートフォン相当は 390×844。マップは 1920×1080 も確認します。
- 祝福・ボス・ショップ・イベントの開始状態は、公開ゲームエンジンの正規アクションで進めたランから保存しています。デッキ、HP、敵の勝敗、ショップ在庫を直接書き換えて作った攻略状態ではありません。
- 各 UI 操作の直後、実際の localStorage とエンジンが事前計算した保存データを全文比較します。選択途中、確定後、次画面への移動後に再読み込み、同じ内容で復元されることを確認します。
- カード選択中は HP・ゴールド・デッキが変化しないこと、確定ボタンの二度押しで報酬が重複しないことも確認します。
- SVG 一覧・レリック発動表示はコンポーネント用ハーネス、マップの 5 状態は進行位置を用意した表示用フィクスチャを使います。これらは通しプレイの検証とは区別します。

レリック一覧では名前・効果に沿う図案、職業・レアリティ・入手経路の装飾、ID ごとの縁の刻印を確認しました。ゴルゲットには頸当て、鎖鎌には鎌・鎖・分銅を描いた図案を追加しています。画像や絵文字をアイコンとして流用していません。

カード効果説明、獲得結果の文章、レリック説明の欠けとページ全体の横方向のはみ出しを検査しています。マップは未到達ノードの情報確認やズーム操作で保存内容が変化せず、接続されたノードの選択でのみ現在位置が更新されました。

## 正規ランでの UI 操作確認

全 5 職業で、選択画面の初期レリック名・効果説明、開始時の祝福 4 択、戦闘開始後の所持アイコンと職業固有 HUD を確認しました。各操作後と再読み込み後の保存内容は事前計算した内容と一致し、110 回のレイアウト検査も成功しています。

最新 182 件のレリック定義を使って正規ランの開始状態を再生成し、以下の 20 フローを両画面幅で確認しました。合計 40 ケース、118 回の UI 操作、276 回のレイアウト検査が成功し、ブラウザの JavaScript 例外は 0 件です。

- 祝福の 4 択からエンシェントを選択し、カード取得・削除・変化・強化とスターター強化版への交換を実行。追加選択前・部分選択・確定・復帰の各状態で保存本文が期待値と一致。
- 条件付きの「？」イベントで選択肢を確定し、対価・所持品・取得時効果を反映してマップへ復帰。
- 全 5 職業で、実際の攻略によるボス撃破後のレアカード 3 枠を表示し、取得・スキップの両方を実行。候補と結果は再読み込み後も不変。
- ボス報酬の取得後、既存の Act 終了画面から Act 2 の祝福 4 択へ進行。
- ショップのレリック購入、ドリーの鏡のカード選択・複製・購入済み表示、会員カードの適用後の価格表示を確認。ポーション 17G、削除 30G、カードは保存済みの各価格を 50% に切り捨てた値と一致。

選択とプレビューで HP・ゴールド・デッキが変わらないこと、確定ボタンの二度押し後も保存内容が一度分だけになることを検査しています。画面の確認だけで効果の成立を判断せず、各操作の後と再読み込み後に localStorage をエンジン計算結果と全文比較しました。

再現用スクリプトは `scripts/browser/relic-ui-fixtures.ts` と `scripts/browser/check-relic-flows.py`。フィクスチャはアプリに配布せず、`/tmp` に生成します。Vite をポート 5282 で起動した環境では次の手順で再実行できます。

```bash
npx esbuild scripts/browser/relic-ui-fixtures.ts --bundle --platform=node --format=esm --outfile=/tmp/spyier-relic-ui-fixtures.mjs
node /tmp/spyier-relic-ui-fixtures.mjs /tmp/spyier-relic-ui-final-fixtures.json
python scripts/browser/check-relic-flows.py
```

Python の Playwright と `/usr/bin/chromium` が必要です。`SPYIER_QA_URL` で接続先、`SPYIER_RELIC_FIXTURES` で入力保存、`SPYIER_RELIC_OUTPUT` で出力先を指定でき、`QA_WIDTH=1366` または `390` で幅ごとに実行できます。

最終ビルドの `vite preview`（`http://127.0.0.1:5284/spyier/`）でも、変化対象の部分選択・確定・結果・復帰、および Act 終了画面から次の祝福 4 択への遷移を実操作で確認しました。両幅で保存本文が一致し、JavaScript 例外は 0 件。Vite の開発用モジュールではなく、`/spyier/assets/` の圧縮済み JS・CSS を読み込む状態の確認です。全 40 ケースの開発時検証とは別に、代表フロー 4 ケースの本番スモークとして数えています。

本番などで代表フローだけを確認する場合は `SPYIER_RELIC_CASES=ancient-transform,boss-to-next-act` を指定できます。指定した名前が存在しない場合は、0 件の成功として扱わず失敗します。

## 自動テスト

`npm test -- src/tests/relic-map-ui.test.ts` は **11 テスト成功**。全レリックの SVG 描画・刻印の識別性、マップの状態表示、HUD の発動識別、5 種類の追加選択、実際の強化・変化・取得結果との一致を確認しています。

スターター交換結果の試験は存在する ID `ref_orobas_fingertip` を使用し、列挙したレリックが見つからない場合は失敗させます。未登録 ID による黙ったスキップは行いません。

## 検証の範囲

Chromium の PC 表示とタッチ対応モバイル表示による自動操作です。実機の iPhone Safari / Android Chrome、人による全 Act の通しプレイ、未実装の資料レリック全件の動作は、この画面検証には含みません。全体のテスト・ビルド・セーブ互換性の結果は更新の進捗記録にまとめます。
