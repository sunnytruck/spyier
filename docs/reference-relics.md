# 添付資料に基づく戦闘レリックの実装

## 対象と方針

追加定義 `src/data/referenceRelics.ts` は 77 件（コモン 15／アンコモン 25／レア 19／ショップ 7／イベント 11）。原資料 `docs/reference/レリック一覧.txt` を CP932 で読み、画像ラベルを取り除いた名前・効果の全文と照合した。スターター、取得時・経済・施設効果、エンシェントは別モジュールで管理する。

この一覧の件数は新しい戦闘定義のみ。既存レリックや他モジュールを合算した総数・未対応理由は全体のレリック監査を参照する。名前だけの定義は取得プールへ登録しない。常時効果は passive、複数の効果は effects 配列へ分割して、効果の一部を省略しない。

## 入手経路と職業

rarity と acquisition は別属性。ショップ限定とイベント限定は通常報酬へ混入しない。資料で職業が明記されているのはスターターのみ。本モジュールでは、鍛造・岩霊・魂札・集中力・オーブ・星・石刃のように固有システムを必要とする 8 件を、そのシステムを持つ職業へ機能上の条件として制限する。これは資料に職業が書かれているという意味ではない。それ以外の攻撃・毒・敏捷・筋力などは全職業で取得できる。

3 ターンごとのように戦闘ごとのリセットを指定しない周期とカード使用・廃棄の周期は、ラン全体で保存される数値カウンターで管理する。ターン内の 3 枚ごとは各ターンでリセットする。

「イカリ？」等の末尾の「？」は原資料の名前であり、通常版より弱い別レリック。画像ラベルとは異なるため削除や同一視をしない。

## 既存の完全一致効果との統合

以下は新規 ID を作らず既存 ID と表示名を維持し、出典名を別属性で関連付ける。

|資料名|維持する既存 ID|共通の効果|
|---|---|---|
|ヴァジュラ|prayer_knuckle|戦闘開始時、筋力 1|
|バックパック|fossil_bookmark|戦闘開始時、追加 2 枚ドロー|
|ランタン|amber_spark|戦闘開始時、エナジー 1|
|ビー玉袋|stone_mask|戦闘開始時、全敵に脆弱 1|
|レッドマスク|ember_lens|戦闘開始時、全敵に脱力 1|

参照資料の「脱力」はエンジン weak、「弱体」（与ダメージ +50% の対象）は vulnerable に対応する。既存カード資料の正規化と同じ対応を使う。

## 検証

`reference-relic-definitions.test.ts` で 77 件の原 CP932 資料・名前・効果全文・レアリティ・出典ハッシュを照合する。各戦闘フックには数値に対する独立した実行結果の検証を用意する。戦闘内の使用順・セーブ・ロード・職業別初期レリックはエンジンと取得系の統合テストで別途検証する。

担当範囲の検証：`npm test -- src/tests/reference-relic-definitions.test.ts` は 161 テスト成功。ストライク参照名、強化アタックの各ヒット補正、毒カードと毒パワーの追加、星を参照する攻撃の補正、最初のカードブロックの倍化、エナジー・ブロックの持越し、右端オーブの追加自動発動は実際のカード使用／ターン終了を通して確認した。全体回帰・最終ビルドの結果は、全体の進捗ドキュメントを参照する。

タングステンの棒は戦闘中の HP 消費・毒・被弾に加え、イベントや祝福の HP 支払いにも共通の軽減処理を適用する。最大 HP 減少には適用しない。トカゲのしっぽの使用済み状態はラン全体の `relicState` に保存し、次の戦闘や再読み込みで復活回数が戻らない。戦闘外の HP 支払いは既存の「生存できる場合のみ選択可」の条件を維持する。

追加監査でゴルゲットと鎖鎌を登録した。`relic-audit-additions.test.ts` の4件は、プレートの被弾条件と保存、鎖鎌の3枚目・6枚目・ターンリセット・保存後の正しい継続を実際のカード使用／敵ターンで検証する。赤い頭蓋骨は `hpThresholdStrength` の型定義のみで実処理がないため保留し、実装済みとして数えない。
