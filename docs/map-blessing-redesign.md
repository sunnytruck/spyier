# マップと祝福確認の再設計（2026-10-21）

## 1. 地図を主役にする

`MapScreen.tsx` からサイドバーをDOMごと削除。章説明・次の3経路ボタン・常設の説明行・モバイル用説明欄を取り除き、コンパクトなヘッダーと全幅の地図にする。旧930px／890pxの幅制限も解除し、画面の残り高さを地図の内部スクロールへ割り当てる。

- ヘッダー：Act／階層名、縮小・標準・拡大、現在地へ。
- 進行：ノードを直接押す。移動可能ノードだけが既存 `chooseNode` アクションを発行し、接続判定はエンジンへ委ねる。
- 詳細：ホバー・キーボードフォーカス・タップで一時表示。未接続／踏破済みノードも閲覧可能だが、進行アクションは発行しない。
- 現在地／進行可能／踏破済み／未到達／移動不可能は既存保存状態から表示し、色・輪郭・チェック・ラベルを併用。
- 拡大縮小は地図の幅・高さ・ノード寸法へ反映。現在地ボタンは横方向も含めて保存済みの位置へ戻す。フロア文字をSVGの横伸びから分離する。
- 新スタイル `map-sanctuary.css` は新しい地図classへ限定し、他画面のCSSを変更しない。文字は読みやすいゴシック体を使い、ボタンは最小44pxのヒット領域で扱う。

`npm run build` とマップ関連3ファイル25テスト成功。入口／合法に進んだ2Fの2状態×1920・1366・390幅の6ケースも成功。sidebar DOMなし、ページの縦横はviewport内、地図幅1848／1311／374px、直接選択後の保存全文と再読込の一致、ブラウザ例外0を確認した。

マップ機能は `f37dff7` でコミット・mainへ通常push済み。追加のブラウザ6ケースでは各倍率の寸法変化、選択不可ノードのキーボード閲覧、地図内部スクロールと現在地復帰、全保存ノード／接続／状態の表示、保存不変を確認した。

## 2. 祝福確認の祭壇

祝福確認だけを専用の祭壇へ変更した。独自SVGの石顔・欠けた石板・ひび・紋章・立体の台座を描き、外側の共通Modalと内側の確認パネルは祝福専用クラスで枠・影を取り除く。共通Modal本体や他画面のモーダルは変更しない。

- 上中央：石像の顔、実際の祝福人物名、祝福名。説明は確定前に効果が発生しない旨の一行に整理。
- 左右：報酬と代償を独自の紋章と実際の数値で表示。呪いの詳細、獲得カード・レリック、強化前後、削除／変化の対象プレビューを維持。
- 下中央：台座の確定ボタンと「選択へ戻る」。長いカード選択でもModal内部をスクロールでき、確定操作は台座に残る。
- 閉じる・Escape・背景クリック・Tabフォーカス管理は既存Modalを利用。閉じても保存された候補や対象を変更せず、確定前に報酬や代償を適用しない。
- 同期refで同一処理中の連打を止め、既存のエンジン側の一度限りの取得処理も維持する。保存形式・祝福抽選・効果は変更しない。
- 受領時に短い光環が広がる。操作を遮らず、既存の受領時間内で終了し、fast／軽減／instant／OS軽減設定に対応。
- 初回は石顔を含む上部から表示し、PC／スマートフォンで表示と操作のはみ出しを調整。文字やボタンをclipで隠して収めない。

## 検証の再実行

`npm test`、`npm run build` 後、`npm run preview -- --port 5284` で本番成果物を起動する。検証環境のPython Playwrightと `/usr/bin/chromium` を利用して、別のターミナルから次を実行できる。

```bash
npx esbuild scripts/browser/two-screens-fixtures.ts --bundle --platform=node --format=esm --outfile=/tmp/two-screens-fixtures.mjs
node /tmp/two-screens-fixtures.mjs /tmp/spyier-two-screens-fixtures.json
IWASON_TWO_SCREENS_URL=http://127.0.0.1:5284/spyier/ python scripts/browser/check-two-screens.py
```

生成スクリプトは対象一覧の末尾からカードを選ぶため、スクロールした先の選択操作も再現できる。ゲーム側にデバッグ用の報酬・HP・マップ変更機能は追加しない。
